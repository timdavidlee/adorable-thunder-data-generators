# add-flow — warehouse-management

## What ran

`/add-flow warehouse-management`. Existing enterprise brief and scrutiny brief were already
in place; this run produced the generator package and wired it into the pipeline.

## What changed

- Created `src/adorable_thunder/make/record_generators/warehouse_management/`:
  - `storage_locations.py` — master dim of physical bins. Encodes the
    `WH{n}-{ZONE}-{AISLE}{RACK}-L{LEVEL}-B{BIN}` naming convention; capacity by zone;
    per-zone empty-rate so STAGING/RETURNS/QUARANTINE turn over more often than BULK/PICK.
    SKU prefix is locked to zone (`PERISH-` for COLD, `HAZ-` for HAZMAT, `PROD-` elsewhere)
    so zone-SKU appropriateness checks stay clean by construction. `current_qty ≤ capacity`
    enforced.
  - `inbound_shipments.py` — supplier-to-warehouse arrivals with ~30% international, and
    `actual_date` clamped to ±3 days of `expected_date` for domestic / ±7 for international.
    `actual_date` is NULL for `pending`/`in_transit` rows.
  - `receipt_lines.py` — putaway lines linked to inbound shipments and storage_locations.
    Receiving accuracy: ~98% of lines have `received_qty == expected_qty`; remainder show
    small over/under discrepancies.
  - `pick_lists.py` — line-level picks for outbound orders. Sources only from pickable
    zones (BULK/PICK/STAGING/COLD/HAZMAT) and matches SKU prefix to source zone.
  - `outbound_shipments.py` — one row per `order_id`, status derived from the rollup of
    its pick-line statuses (any exception → `exception`; all pending → `pending`; mixed
    pending+complete → `picking`; all complete → `shipped`/`delivered`). `ship_date` and
    `tracking_number` are NULL until status reaches shipped/delivered.
  - `cycle_counts.py` — bucketed variance distribution: ~85% exact, ~13% small (±1–3),
    ~1.5% mid (1–2.5%), ~0.5% large (3–8%). `system_qty` sourced from
    `storage_locations.current_qty` so cycle counts are consistent with the bin master.
  - `flow.py` + `__init__.py` — exposes `GeneratorConfig` and `FLOW_SCHEMAS`.
  - `briefs/TODO.md` — empty wishlist seed.
- Edited `src/adorable_thunder/make/database/inject_into_pg.py` to import
  `WMGeneratorConfig`/`WM_FLOW_SCHEMAS` and add them to `ALL_FLOW_GENERATORS`.
- Updated `BRIEFS.md`: warehouse-management row flipped from `brief only` to
  `has dataset`, last-updated set to 2026-04-28.

## Verification

- `uv run pyright` (strict mode) on the package and `inject_into_pg.py`: 0 errors.
- `inject_into_pg --flow warehouse_management --n-samples 1000 --drop` succeeded; loaded
  6 tables (1000/1000/1547/2440/1000/1000 rows).
- Spot SQL checks against the loaded data:
  - 0 inbound rows with `actual_date` more than 7 days before `expected_date`.
  - 0 storage_locations with `current_qty > capacity`.
  - Zone distribution roughly matches brief weights (BULK 39%, PICK 31%, STAGING 10%,
    COLD 8%, RETURNS 5%, HAZMAT 4%, QUARANTINE 3%).
  - Outbound status mix: delivered 43%, shipped 24%, picking 17%, exception 13%,
    pending 3%.
  - Cycle counts: 86% exact match, 6.6% over the 1% investigation threshold.

## Follow-ups

- Cycle-count investigation rate (6.6%) is a hair above the brief's <1–2% target. The
  per-bucket weights in `cycle_counts.py` (`_MID_VARIANCE_RATE`, `_LARGE_VARIANCE_RATE`)
  can be lowered if `/scrutinize` flags it.
- Outbound `exception` rate (13%) is high relative to the 99.5–99.9% pick-accuracy
  benchmark — comes from the 5% per-line exception weight in `pick_lists.py` compounding
  across 2–4 lines per order. Likely worth lowering the per-line exception weight in a
  follow-up `/generate-and-scrutinize` pass.
- No FK references encoded in the schema DDL (matches existing flows). Cross-table joins
  rely on the `llm_description` documenting which columns join.
