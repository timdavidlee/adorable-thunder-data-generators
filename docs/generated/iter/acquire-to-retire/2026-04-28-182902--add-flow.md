# add-flow — acquire-to-retire

## What ran

`/add-flow acquire-to-retire`. Briefs already existed under `enterprise_dataflow_briefs/` and `scrutinize/specific_briefs/`; the generator package was the missing piece.

## What changed

- New package `src/adorable_thunder/make/record_generators/acquire_to_retire/` with three stages:
  - `assets.py` — Asset Master. Lognormal cost per class (IT/office/vehicle/leasehold/building/intangible/machinery), useful-life from class, salvage 0 or 10%, status assigned via age vs. useful_life so the portfolio mix lands at brief targets (~75% in_service, ~15% fully_depreciated, ~10% disposed, ~1% planned).
  - `depreciation_runs.py` — Per-asset monthly depreciation snapshots for the trailing 6 active months. Math holds row-by-row: `book_value_end = book_value_start − depreciation_amount`, floored at salvage; `accumulated_depreciation = cost − book_value_end`. Disposed assets stop at the disposal month.
  - `disposals.py` — One row per disposed asset. Proceeds are class-appropriate fractions of cost (IT 10–30%, vehicles 30–50%, buildings 60–150%, leasehold 0–10%, etc.). Non-cash retirements (`SCRAPPED`, `DONATED`, `LOST`) zero out proceeds. `book_value_at_disposal` is reproduced from the same straight-line math used in the runs table so the two reconcile. `gain_loss = proceeds − book_value_at_disposal`.
- `__init__.py` and `flow.py` wire the three stages.
- `briefs/TODO.md` seeded for `/insights-wishlist` to append to.
- `inject_into_pg.py` — added `A2R` imports (alphabetically before `C2C`) and appended `(A2RGeneratorConfig, A2R_FLOW_SCHEMAS)` to `ALL_FLOW_GENERATORS`.
- `BRIEFS.md` row updated: `brief only` → `has dataset`, last updated 2026-04-28.

## Verification

- `ruff check` and `pyright` both clean on new files and `inject_into_pg.py`.
- `inject_into_pg --flow acquire_to_retire --n-samples 1000 --drop` succeeded; loaded 1000 assets / 5879 depreciation runs / 95 disposals.
- Status mix on n=1000: in_service 74.4%, fully_depreciated 15.4%, disposed 9.5%, planned 0.7% — within brief benchmarks.
- Math invariants verified via SQL: zero rows where `book_value_end ≠ book_value_start − depreciation_amount` (above salvage floor), zero disposals with `disposal_date ≤ acquisition_date`, zero non-cash disposals with proceeds, zero rows where `gain_loss ≠ proceeds − book_value_at_disposal`.

## Follow-ups

- Half-year convention not modeled — depreciation begins the month after acquisition, full-month basis. Real ERPs sometimes use mid-month or half-year. Acceptable simplification for now.
- The `depreciation_method` field is recorded (`STRAIGHT_LINE`, `DECLINING_BALANCE`, `SUM_OF_YEARS`) but the runs table always uses straight-line math regardless. Scrutinize will likely flag this — leave it for a future iteration.
- BOM/intercompany overlaps with R2R (depreciation hits the GL) and P2P (acquisition hits AP) are not wired across flows. Acceptable since the project keeps flows independent today.
